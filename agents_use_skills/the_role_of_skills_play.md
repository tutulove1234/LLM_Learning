在vibe coding中，Skills将AI编码agent从通用编码助理转变为理解你开发实践的工程师。

将Skills想象为一个可重用的工程知识和工作流程。

# Skills 所扮演的角色

|角色|解释|
|:---|:---|
|知识注入|给AI一个领域特定的知识和技术上下文|
|工作流定义|教会AI如何处理和执行特定的任务|
|质量控制|定义编码标准，测试需求，和评审规则|
|一致性|让AI在不同的任务之间都遵循相同的工程实践|
|可重用性|避免在每次对话中都重复解释相同的指令|

# 为什么他们是重要的？

当没有Skills时候：
* AI 严重依赖于你的提示词。（因此你的提示词必须是高质量的）
* 你要重复解释你的项目约定。（比如如何执行、如何测试、如和review等）
* 每次的结果可能是不一致的。
* AI 可能会做出技术上不正确的架构决策。

当有Skills的时候：
* AI 可以重用那些已经建立的工程知识。
* 它会按照预定义的工作流来执行。
* 它会产出更可预测的结果。
* 你可以将注意力集中在架构层面的决定，而不是重复地解释项目的实现细节。

# 我的心智模型
考虑一个工程师团队：
* LLM = 一个聪明的工程师
* Prompt = 你分配的任务
* Skills = 工程手册和标准操作流程
* Tools = 工程师的开发环境和装备
* Context = 项目当前的状态和历史

# 我的结论
Skills 的真正价值不是使AI生成代码的速度更快。它将你的工程经验、技术上的决策和开发方法论转换成可重用的指令。

这也是为什么vibe coding从一个“让AI写代码”转换成“构建一个AI协助的工程工作流”。
